# iMessage Bot — Plan

## Goal
Send personalized iMessage to ~400 contacts from macOS Contacts whose name contains NY / NYC / New York / New York City. Two-step (scan → review CSV → send). Templates IT/EN, language auto-detected from past chat history. Deterministic, no LLM.

## Constraints
- macOS only (uses Contacts framework, chat.db, Messages.app via AppleScript).
- iMessage only — skip non-iMessage contacts.
- Must avoid Apple spam ban (no public rate limit; ratio outbound/inbound matters).
- Idempotent — can resume after crash.
- User reviews CSV before send.

## Architecture

```
imessage-bot/
├── config.yaml          # filter keywords, templates, delays
├── scan.py              # entry: build preview.csv
├── send.py              # entry: read CSV → send
├── lib/
│   ├── contacts.py      # macOS Contacts → list
│   ├── filter.py        # whole-word regex match
│   ├── chatdb.py        # query chat.db for past messages
│   ├── language.py      # IT vs EN heuristic from past msgs
│   ├── name.py          # extract first name, strip NY tags
│   ├── imessage.py      # check iMessage availability per handle
│   └── messenger.py     # AppleScript send wrapper
├── output/
│   ├── preview.csv      # generated by scan, edited by user
│   └── sent.json        # per-contact log (idempotent)
└── README.md
```

## Tech stack
- Python 3.11+
- `pyobjc-framework-Contacts` — read macOS Contacts
- `sqlite3` stdlib — read chat.db
- `langdetect` or simple keyword heuristic — language ID
- `subprocess` + `osascript` — Messages.app control
- `typer` — CLI
- `rich` — terminal UI / progress

## Workflow

### Phase 1 — `scan`
1. Load all contacts from macOS Contacts.
2. Filter whole-word regex `\b(NY|NYC|New York|New York City)\b` (case-insensitive) on `givenName + familyName + organization`.
3. For each match:
   - Pick handle: prefer iMessage-registered phone/email (check via Messages.app or handle table in chat.db).
   - Query chat.db for last 30 messages exchanged with handle.
   - Detect language: IT vs EN. Default IT if zero history or ambiguous.
   - Extract first name: strip "NY", "NYC", "New York", "New York City" tokens, take first remaining token.
   - Render template:
     - IT: `Ciao {first_name}, come stai?`
     - EN: `Hey {first_name}, how are you?`
   - Mark `has_imessage` flag.
4. Write `output/preview.csv` with columns:
   - `contact_id, full_name, first_name, handle, handle_type (phone/email), language, has_imessage, past_msg_count, message, skip_reason`
5. Print summary: total matched, with iMessage, by language, skipped reasons.

### Phase 2 — review (user)
User opens `preview.csv` in Numbers/Excel. Deletes rows or sets `skip_reason` to exclude. Saves.

### Phase 3 — `send`
1. Read `preview.csv` and `sent.json`.
2. Filter rows: `has_imessage=true` AND no `skip_reason` AND not in `sent.json`.
3. Print final count + ETA. Wait 10 sec (chance to Ctrl-C).
4. Loop:
   - Random delay 8–20 sec between sends.
   - Hourly cap: max 60 sends/hour (configurable).
   - Daily cap: max 150/day (configurable). Stop & resume tomorrow.
   - For each: invoke AppleScript `tell application "Messages" to send "{message}" to buddy "{handle}" of service ...`.
   - Append to `sent.json` immediately after each send: `{contact_id, handle, sent_at, message_hash}`.
5. On Ctrl-C: graceful exit, log saved.
6. Re-running resumes from last unsent.

## Safety layers (defense in depth)
1. **Whole-word regex** — no false match ("Tony", "Anya").
2. **Manual CSV review** — user sees full list + messages before send.
3. **iMessage-only filter** — skip non-blue contacts.
4. **Random jitter delay** — 8–20 sec.
5. **Hourly + daily cap** — spread 400 messages over ~3 days max ban risk.
6. **Idempotent log** — no duplicate sends.
7. **Dry-run flag on send** (`--dry-run`) — prints AppleScript commands without executing.
8. **First-name fallback** — if extraction fails, use full name minus NY tags.
9. **Pre-flight check** — before sending, verify Messages.app running, Full Disk Access OK, chat.db readable.

## Risks
- **Apple ban**: 400 cold outbound with ~0 reply ratio = spam profile. Mitigation: low daily cap (150), spread 3 days, recommend warm-up batch (50 first day, monitor for replies, then scale).
- **Full Disk Access**: required for chat.db. User must grant manually in System Settings.
- **attributedBody hex blob**: modern macOS stores message body encoded. Need typedstream parser (lib `imessage-exporter` or manual). Mitigation: for language detection we only need `text` column when populated, fallback to first 100 messages where text non-null.
- **Phone normalization**: contacts store phones in many formats (`+1 (212) 555…`, `212-555…`). Need E.164 normalization before matching handle table. Use `phonenumbers` lib.
- **iMessage availability detection**: AppleScript can throw if buddy not found, but iMessage delivery failure is silent. Best heuristic: contact had past iMessage (blue) in chat.db → safe.
